    ON/QC region scopes proposal¶

    Proposal for discussion

    Region scopes stop local chatter from flooding the whole network. Today's setup is hard to follow, so this proposal cuts it down to three codes that everyone in Ontario and Québec can remember.

    • Not adopted yet
    • Ontario + Québec pilot
    • Repeater firmware 1.16+
    • MeshCore app 1.43+

    The short version¶

    There are three levels of scope. Every repeater carries one code from each level: its city, its province, and onqc. When you send a message, you choose which level to use, and that decides how far it travels.

    City

    yow yul yqb

    Your local area. Same codes as MeshMapper.

    Province

    on qc

    Every repeater in that province.

    Mesh

    onqc

    Every repeater in Ontario and Québec.

    • Repeaters carry their city, their province, and onqc.
    • Phones use onqc as their default, so direct messages reach anyone.
    • Local channels such as #public are set to your city, so chatter stays local.
    • Messages with no scope keep working during the pilot.

    What a scope is¶

    A scope is a short name attached to a message, such as yow. Repeaters use it to decide whether to pass the message on.

    A scope is not encryption and not a GPS fence. Anyone can read the name, and it has nothing to do with where you are. It is only a label that says "repeaters that carry this name, please forward this."

    Your app turns the name into a small code and puts it in the message header. Every repeater keeps a list of names it will forward. When a message arrives, the repeater checks the code against its list.

    How a repeater decides¶

    Here is an Ottawa repeater under this proposal, and what it does with five different messages.

    Three details catch people out:

    • Spelling must be exact. yow, YOW and ott are three different names. A phone set to yow is ignored by a repeater that only carries ott.
    • Only floods are checked. Once a direct message has a known path, it goes straight along that path and scopes no longer matter.
    • There is no inheritance. Carrying on does not mean carrying yow. Each name has to be on the list by itself.

    The three levels¶

    Why airport codes?¶

    • They are the same codes MeshMapper already uses, for example yow.meshmapper.net.
    • There are no accents or capital letters to get wrong. montréal, Montreal and montreal would be three different scopes.
    • They are easy to split later. If Renfrew wants its own area one day, it can use its own airport code and still keep on and onqc. Nothing else changes.

    Always write the code with its area the first time, for example yow (Ottawa / NCR area), so people learn it.

    Reading region def yow|* on|* onqc¶

    region def builds a repeater's list in one line. It keeps a cursor that starts at the top, *. Each name is created under the cursor, and |* jumps the cursor back to the top.

    region def only adds or moves names. It never deletes the ones already there. Run region afterwards to see the full list.

    Repeater setup¶

    Step 1: Clear any old regions¶

    Many repeaters already have regions from the older setup, such as can, on-alg or ott. region def never deletes anything, so clear them first.

    1. Run region to list what is there.
    2. Remove every name except * with region remove <name>. Start with the most indented line and work up. If you see Err - not empty, a name is still indented under it, so remove that one first.
    3. Run region save.

    For example, a repeater set up with the old Ottawa path:

    region remove ott
region remove on-alg
region remove on
region remove can
region save

    Removing on is fine. The region settings in step 3 add it back. Run region again, and you should only see * F.

    Step 2: Standard MeshCore Canada settings¶

    set path.hash.mode 2
set advert.interval 240
set flood.advert.interval 47
set flood.max 16
    path.hash.mode 2
    Uses 3-byte repeater IDs in message paths, so fewer repeaters share an ID.
    advert.interval 240
    Announces this repeater to direct neighbours every 4 hours.
    flood.advert.interval 47
    Announces this repeater across the network every 47 hours.
    flood.max 16
    No flood message travels more than 16 hops, scoped or not.

    Step 3: Region settings¶

    Your city code is your MeshMapper zone. Open MeshMapper, find the zone your repeater sits in, and use its code. It is a map everyone already uses, so there is nothing new to look up.

    The pattern is always the same:

    region def <city>|* <on or qc>|* onqc

    Examples:

    region def yow|* on|* onqc
region allowf *
region default yow
region save

    region def yow|* qc|* onqc
region allowf *
region default yow
region save

    region def yul|* qc|* onqc
region allowf *
region default yul
region save

    region def yqb|* qc|* onqc
region allowf *
region default yqb
region save
    region def …
    Carry your city, your province, and onqc.
    region allowf *
    Also forward messages with no scope. This is already on by default. We set it anyway so you can see it.
    region default yow
    This repeater's own adverts use your city's scope, so they stay local.
    region save
    Keeps the region settings after a reboot. The set commands save by themselves.

    To check, run region. For Ottawa you should see:

    * F
 yow F
 on F
 onqc F

    F means "flood allowed": the repeater forwards that name.

    Bridge repeaters¶

    A repeater that links two city zones on purpose carries both city codes. For example, a repeater in Rigaud sits in the yul zone and links Montréal to the Ottawa zone:

    region def yul|* yow|* qc|* onqc
region allowf *
region default yul
region save

    It forwards Ottawa and Montréal city messages, plus qc and onqc. Its own adverts stay in its home zone, yul. Only add a neighbouring city when the repeater really links the two areas, or city messages will leak further than people expect.

    Allow or drop, quick reference¶

    Command What it does
    region allowf <name> Forward messages with that name
    region denyf <name> Drop messages with that name. The repeater still receives them itself.
    <name> Can be * for messages with no scope, or a code such as yow
    set flood.max.unscoped <hops> A separate hop limit for messages with no scope. It only matters when it is lower than flood.max. 0 has the same effect as region denyf *.
    region save Always run it after allowf or denyf

    Phone and companion setup¶

    1. Open the MeshCore app, then Settings → Experimental Settings → Default Region Scope. Add onqc and select it.
    2. Open each local channel, such as #public. Use the channel menu, then Set Region Scope, and pick your city code, for example yow.
    3. For a channel meant to reach further, pick on, qc or onqc instead.

    Why the phone default is onqc¶

    You cannot pick a scope for a single direct message. When a DM has no known path yet, it floods using your default scope. The reply that tells your phone the path comes back using your contact's default scope.

    The catch: a channel with no scope of its own also uses your default. With onqc as the default, an unscoped #public would reach all of Ontario and Québec. That is why step 2 of the phone setup sets local channels to your city.

    Rollout¶

    1. Repeaters

      Owners clear old regions, add their three codes and keep * allowed. Nothing breaks for anyone.

    2. Phones

      Users set their default to onqc and set local channels to their city.

    3. Cutover

      On an agreed date, repeaters run set flood.max.unscoped 3. Messages with no scope then stay within 3 hops, while scoped messages still reach 16.

    Things to know¶

    • Repeater adverts stay in their city. Montréal users will not see Ottawa repeaters through flood adverts.
    • 16 hops has to be enough. flood.max applies to onqc too. If the longest real path across the mesh is longer than 16 hops, cross-mesh messages will stop part way.
    • Versions: region def needs repeater firmware 1.16 or newer. Default scope in the app needs MeshCore 1.43 or newer.

    Next steps¶

    • Agree on the list of city codes for Ontario and Québec.
    • Add a "find your town" lookup to meshcore.ca that shows your code.
    • Publish clean-up and setup commands for each city.
    • Add a simple Ontario and Québec mode to the repeater configurator.
    • Other provinces keep the current setup until the pilot has proven itself.
